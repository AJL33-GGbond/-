# 时间不是忘记，而是放下

> 一款有明确终点的 AI 书信网页应用，让用户表达思念，整理未说完的话。

本仓库文档记录产品规划与开发路线，功能完成情况以任务清单为准。项目首先面向开发者及少量成年朋友进行免费邀请测试，后续再评估公开上线。

## 产品概述

用户导入与故人的聊天记录，AI 参考对方的语言习惯生成回信。通信对象可以是已故亲友、前任或失联朋友。

**回信由 AI 生成，不代表本人真实的想法、回应或意愿。** 产品不保证准确还原对方，也不将模拟回信描述为真实的和解或关系恢复。

## 已确定的规则

| 项目 | 规则 |
| --- | --- |
| 平台 | 网页，兼顾手机浏览器 |
| 测试范围 | 开发者与受邀请的成年朋友 |
| 收费 | 内测免费 |
| 通信对象 | 每个账号一位 |
| 寄信频率 | 每天最多成功寄出一封，名额不累积 |
| 通信总量 | 累计最多 99 封，漏写不扣次数 |
| 回信时间 | 正常情况下，寄出约 5 分钟后投递 |
| 结束方式 | 第 99 封来信对应一封告别回信 |
| 可见范围 | 仅账号本人可见 |

这是 **99 封信**，不是连续 99 天。模型或网络故障导致回信延迟时，需要显示状态并有限重试，不重复计数。

### 建议采用的内测默认值

以下为实施建议，尚需在开发时最终确认：

- 每日以马来西亚时间（Asia/Kuala_Lumpur）凌晨 0 点为分界，页面明确说明。
- 正式寄出第一封后锁定通信对象。
- 允许用户提前告别，明确确认后结束通信。
- 结束后保留只读信箱，可导出或删除，不自动重开。
- 第一版通过网页收信，暂不提供邮件通知。

## 用户流程

1. 使用邀请码注册，确认成年并阅读资料使用说明。
2. 创建通信对象，填写双方称呼、关系与可选背景。
3. 粘贴聊天或上传 TXT，确认双方发言并排除不希望使用的内容。
4. 查看语气预览，补充或调整表达习惯。
5. 编写并保存草稿，确认后正式寄出。
6. 等待约 5 分钟，在私人信箱中阅读回信。
7. 继续通信，累计第 99 封时收到告别信。
8. 结束后阅读、导出或删除书信。

## AI 回信设计

第一版调用已有模型接口，无需自行训练模型。回信参考以下资料：

1. 双方称呼及对方的语言习惯。
2. 与当前来信相关、有来源依据的聊天片段。
3. 此前书信的必要摘要。
4. 当前来信与通信进度。

不必每次发送全部聊天记录，应控制上下文长度、私人信息传输量和费用。

### 内容要求

- 回应当前来信，减少套话和重复说教。
- 不将虚构经历写成双方真实记忆。
- 不声称自己是真实本人。
- 不通过内疚或情感依赖催促用户继续使用。
- 对仍在世的对象，不声称本人已原谅、同意或愿意恢复关系。
- 对明确的即时自伤危险，切换为直接的支持回应。
- 告别信不邀请继续通信，不以付费延长打破终点。

## 技术方案

面向具有 Java 基础的开发者，采用单个 Spring Boot 应用，逐步学习和实现。

| 部分 | 初步选择 | 用途 |
| --- | --- | --- |
| 开发工具 | Visual Studio Code（VS Code） | 编写、运行和调试项目 |
| 语言 | Java | 业务开发 |
| 后端 | Spring Boot | 账号、上传、寄信与 AI 调用 |
| 网页 | Thymeleaf、HTML、CSS、少量 JavaScript | 页面与手机适配 |
| 数据库 | MySQL | 用户、通信对象、书信与任务 |
| 延迟处理 | 数据库任务表与定时任务 | 到期投递、重试与重启恢复 |
| AI | 后端调用模型接口 | 语气资料与回信生成 |
| 文件 | 私有存储 | 必要的上传文件 |

模型供应商、部署服务和具体依赖版本在实施时确认。

### VS Code 开发环境

本项目使用 **VS Code** 完成 Java 后端和网页开发。

按顺序准备：

1. 安装 VS Code 和 JDK。JDK 需要单独安装，版本在创建项目时与 Spring Boot 的要求匹配。
2. 在 VS Code 扩展面板安装 **Extension Pack for Java**，用于 Java 代码补全、运行、调试和测试。
3. 安装 **Spring Boot Extension Pack**，用于创建和运行 Spring Boot 项目。
4. 安装 Git；在实现数据库存储前安装并配置 MySQL。
5. 在 VS Code 终端运行 `java -version`、`javac -version` 和 `git --version`，确认工具可用。

创建项目时，打开命令面板，搜索 `Spring Initializr`，选择创建 Maven 项目，再选择 Java 和适用的 Spring Boot 版本。用 VS Code 打开生成的项目根目录，等待依赖加载完成后运行应用，在浏览器中验证页面。

第一步先完成网页启动，再接入 Thymeleaf 和数据库。日常在 VS Code 中编辑、调试和提交代码，在浏览器中检查页面与书信流程。

参考：[VS Code Java 开发指南](https://code.visualstudio.com/docs/languages/java)、[Spring Boot 配置指南](https://code.visualstudio.com/docs/java/java-spring-boot)。

### 核心数据

- 用户与邀请码。
- 通信对象。
- 导入记录、聊天消息与语气资料。
- 来信、回信、草稿与累计进度。
- 回信任务、预计投递时间、重试次数与状态。

### 实现要点

- 延迟由后端持久化任务控制，不能只靠网页倒计时。
- 可在寄出后后台生成，到投递时间后才允许读取正文。
- 保存来信、更新次数与创建任务应保持一致。
- 重复提交或重复执行任务不能产生重复寄信、回信或扣次数。
- 服务器重启后可恢复未完成任务。
- API 密钥只保存在后端环境配置中，不进入网页或 Git。
- 使用成熟的登录组件和安全密码哈希。
- 所有读取、修改、导出和删除操作都检查数据归属。

## 10 周开发时间线

预计每周投入 **12～15 小时**，适合边学边做。若每周只能投入 6～8 小时，可将每周任务拆成两周。时间为估算，按验收结果推进。

### 第 1 周：搭建项目并保存一封信

**目标：在网页输入内容，保存后重新打开仍能看到。**

- [ ] 准备 JDK、VS Code、MySQL 和 Git。
- [ ] 安装 Extension Pack for Java 与 Spring Boot Extension Pack。
- [ ] 学习 HTTP、Spring Boot Controller、HTML 表单和基础 SQL。
- [ ] 创建项目，接入 Thymeleaf 与数据库。
- [ ] 实现输入正文、保存草稿和读取内容。

**验收：** 项目能启动，信件重启后仍存在，空白内容不能正式寄出。

### 第 2 周：完成基础书信页面

**目标：跑通写草稿、修改、寄出和查看。**

- [ ] 分离 Controller、Service、数据访问与页面职责。
- [ ] 增加信件编号、正文、时间和状态。
- [ ] 完成写信页、信箱页、详情页。
- [ ] 草稿可修改，正式寄出前确认，寄出后正文锁定。
- [ ] 完成基础手机适配。

**验收：** 手机和电脑均能完成基础书信操作。

### 第 3 周：接入 AI

**目标：使用虚构聊天生成并保存回信。**

- [ ] 选择可用模型接口，确认费用并设置测试额度。
- [ ] 从后端调用模型，安全配置密钥。
- [ ] 准备虚构聊天、称呼和不同主题的来信。
- [ ] 编写回信指令，建立来信与回信关联。
- [ ] 显示调用失败状态。

**验收：** 人工检查日常分享、思念、遗憾等来信的回复，确认回应主题且没有明显虚构往事。

### 第 4 周：实现延迟回信

**目标：关闭网页后，仍能在约 5 分钟后收信。**

- [ ] 创建持久化回信任务和最早投递时间。
- [ ] 后台生成回信，到期后开放阅读。
- [ ] 显示等待、送达和延迟状态。
- [ ] 实现有限重试与重复执行保护。
- [ ] 阻止接口提前返回未投递的回信正文。

**验收：** 关闭浏览器不影响任务；后端重启可恢复；失败不丢信、不重复回信。

### 第 5 周：加入账号和通信对象

**目标：不同用户只能访问自己的资料。**

- [ ] 邀请码注册、成年确认与使用说明。
- [ ] 登录、退出与安全密码保存。
- [ ] 创建通信对象及一账号一对象约束。
- [ ] 为书信和资料接口加入归属检查。

**验收：** 使用两个账号验证，修改网址或请求中的编号无法访问他人内容。

### 第 6 周：导入聊天并生成语气资料

**目标：使用粘贴文字或 TXT 建立对象语气。**

- [ ] 定义并展示支持的文字格式示例。
- [ ] 实现粘贴和 TXT 上传。
- [ ] 展示解析结果，确认双方身份。
- [ ] 允许排除内容，对无法解析的格式明确提示。
- [ ] 提取语气资料并提供预览与补充入口。
- [ ] 限制预览调用频率，预览不计入寄信次数。

**验收：** 不混淆双方发言；更换资料后，回信表达有合理变化。

### 第 7 周：实现次数限制与告别

**目标：完整执行每日一次和累计 99 封规则。**

- [ ] 实现每日分界与下次可寄时间。
- [ ] 仅正式寄出计数，预览和重试不重复计数。
- [ ] 防止多窗口和连续点击突破限制。
- [ ] 临近结束提示，第 99 次生成告别信。
- [ ] 结束后关闭寄信入口，保留只读信箱。
- [ ] 若采用提前告别，处理与未送达信件的冲突。

**验收：** 模拟第 98、99、100 次、跨午夜和并发提交；测试加速开关不在内测环境开放。

### 第 8 周：完成隐私、删除和费用控制

**目标：具备接收真实私人资料的基本条件。**

- [ ] 说明模型资料传输、保存期限和删除方式。
- [ ] 删除上传资料及其衍生语气数据。
- [ ] 删除账号关联数据并取消待处理任务。
- [ ] 明确备份清理期限。
- [ ] 导出书信为 TXT 或简单 HTML。
- [ ] 限制上传大小、文字长度、调用频率、重试和总费用。
- [ ] 检查日志、页面安全展示及上传内容对模型指令的干扰。
- [ ] 实现明确危险来信的支持回应路径。

**验收：** 导出可用；删除后页面和接口无法读取；异常请求受到限制。

### 第 9 周：部署与上线前检查

**目标：受邀请用户可以通过 HTTPS 网页使用。**

- [ ] 选择部署服务并配置应用、数据库和 HTTPS。
- [ ] 分开开发与内测数据库、配置和密钥。
- [ ] 关闭调试输出和测试捷径。
- [ ] 配置异常记录、任务监控、备份和额度监控。
- [ ] 验证一次数据库备份恢复。
- [ ] 使用虚构资料演练注册到删除的完整流程。
- [ ] 检查模型故障、重复提交、会话过期、重启和跨账号访问。

**验收：** 手机和电脑可用，没有已知的串号、密钥泄露、丢信或重复计数问题。

### 第 10 周：邀请朋友内测

**目标：邀请 3～5 位成年朋友体验并修复问题。**

- [ ] 先邀请 1～2 位朋友，观察几天。
- [ ] 修复影响使用的问题，再扩大到其余朋友。
- [ ] 收集导入难度、回信语气、编造内容、等待体验和故障反馈。
- [ ] 默认不要求提供私人书信；由用户主动选择可分享的片段。
- [ ] 整理下一阶段任务。

**验收：** 朋友能独立完成使用流程，关键问题得到处理。完整 99 封体验仍需长期观察。

## 内测问题优先级

| 优先级 | 问题 |
| --- | --- |
| 最高 | 私人数据泄露、越权访问、数据丢失 |
| 高 | 无法寄信、回信失败、计数错误、费用失控 |
| 中 | 回信质量、导入困难、状态不清楚 |
| 低 | 配色、动画、信纸装饰 |

若进度落后，优先推迟装饰、更多导入格式和通知功能，保留账号隔离、计数一致性、任务恢复与删除功能。

## 每次开发的工作方式

以两小时为例：

1. 20 分钟：学习当前功能需要的知识。
2. 80 分钟：完成一个可验证的小功能。
3. 20 分钟：验证、提交 Git、记录下一步。

开发期间使用虚构资料；真实聊天、私人书信、密钥、数据库备份及运行日志不得上传到公开 GitHub 仓库。

**第一个里程碑：做出可以写信、保存并重新打开的网页。**
